# מדידה — מעקב אישי

אפליקציית מדידה אישית למשתמש יחיד, בעברית, RTL, מותקנת כ-PWA על אייפון.

**https://shondek.github.io/Weight-loss-track/** — לפתוח ב-Safari
ולהוסיף למסך הבית (ראה [התקנה על אייפון](#התקנה-על-אייפון)).

**זה כלי מדידה, לא אפליקציית כושר.** היא רושמת משקל, מותניים ואימונים,
מחשבת ממוצעים שבועיים, ומייצאת דוח שבועי להדבקה בצ'אט לצורך ניתוח.

היא לא נותנת המלצות, לא מחשבת קלוריות, לא מציגה יעדים, לא צובעת הצלחה
בירוק ולא מעודדת. היא מציגה מספרים ומסמנת מה חסר. הניתוח נעשה בצ'אט.

העיקרון שמקודד בממשק: **החלטות מתקבלות רק מממוצע שבועי של 7 שקילות.**
שבוע חלקי מסומן תמיד כ"חלקי (n/7)", ושורת ההשוואה בין שבועות פשוט לא
קיימת בו — לא בממשק ולא בדוח.

## הרצה מקומית

```bash
npm install
npm run dev        # http://localhost:5173
```

## בדיקות

```bash
npm test           # Vitest על שכבת הלוגיקה

```

הבדיקות מריצות `TZ=Asia/Jerusalem` (מוגדר ב-`vitest.config.ts`) כדי
שמעברי שעון קיץ/חורף ייבדקו באמת ולא בזמן UTC.

## בנייה

```bash
npm run build      # tsc --noEmit + vite build → dist/
npm run preview    # מגיש את dist/ לבדיקה
```

הבנייה מייצרת גם `dist/sw.js` עם רשימת precache מדויקת של קבצי הבנייה
(`scripts/sw-plugin.ts`). אין תלות ב-workbox.

## פריסה — איך מגיעים לכתובת

האפליקציה חייבת להיות מוגשת מ-**HTTPS** כדי שאפשר יהיה להתקין אותה
במסך הבית. קובץ שנפתח מהדיסק (`file://`) או `npm run dev` ברשת
הביתית לא יעבדו — הדפדפן לא ירשום service worker בלי הקשר מאובטח.

### הדרך המובנית: GitHub Pages

`.github/workflows/deploy.yml` בונה, מריץ את הבדיקות ומפרסם בכל דחיפה
לענף. בדיקה שנכשלת עוצרת את הפריסה.

ההגדרה בריפו נעשית פעם אחת: **Settings ← Pages ← Source: GitHub
Actions**. בריפו הזה זה כבר בוצע.

שתי דרישות מוקדמות:

- **הריפו חייב להיות ציבורי** (בחשבון חינמי). בריפו פרטי האפשרות
  `GitHub Actions` ב-Settings ← Pages פשוט לא מוצעת.
- **את שלב 1 אי אפשר לאוטומט.** `actions/configure-pages` תומך
  ב-`enablement: true`, אבל `GITHUB_TOKEN` חוזר עם
  `Resource not accessible by integration` — גם בריפו ציבורי, וגם עם
  `permissions: pages: write`. יצירת אתר Pages היא פעולה ברמת admin.

אם שלב `deploy` נכשל אחרי ההפעלה עם שגיאה על **environment protection
rules**, הסביבה `github-pages` מוגבלת לענף ברירת המחדל. שתי אפשרויות:
למזג את הענף ל-`main`, או להוסיף אותו ב-**Settings ← Environments ←
github-pages ← Deployment branches**.

### בלי GitHub Pages בכלל

כל ריצה מעלה ארטיפקט בשם `dist` (גם כשהפריסה נעצרת). להוריד אותו
מלשונית **Actions**, לפרוס את ה-zip, ולגרור את התיקייה ל-
[Netlify Drop](https://app.netlify.com/drop) — מתקבלת כתובת HTTPS
מיידית בלי חשבון. אפשר גם לחבר את הריפו ל-Cloudflare Pages או
ל-Netlify עם `npm run build` ותיקיית פלט `dist`.

מכאן כל דחיפה לענף בונה, מריץ את הבדיקות, ומפרסם מחדש. בנייה שבורה
או בדיקה שנכשלת עוצרות את הפריסה.

### חלופות

`dist/` הוא אתר סטטי לגמרי. אפשר לגרור אותו ל-Netlify Drop, או לחבר
את הריפו ל-Cloudflare Pages / Netlify / Vercel עם `npm run build`
ותיקיית פלט `dist`. אין ראוטינג ואין צורך ב-rewrites.

`base` הוא `./`, ולכן תת-תיקייה עובדת בלי הגדרה נוספת. נבדק: scope של
ה-service worker, `start_url` של המניפסט, האייקונים והעבודה אופליין —
כולם נפתרים נכון גם מתוך `/<repo>/`.

מומלץ (לא חובה): להגיש את `sw.js` עם `Cache-Control: no-cache`, כדי
שעדכון יגיע מיד. הרישום כבר מבקש `updateViaCache: 'none'`.

## התקנה על אייפון

1. לפתוח את הכתובת ב-**Safari**. לא Chrome ולא מתוך אפליקציה אחרת —
   רק Safari יכול להתקין למסך הבית ב-iOS.
2. כפתור השיתוף (הריבוע עם החץ) ← לגלול ← **הוסף למסך הבית** ← הוסף.
3. לפתוח מהאייקון. האפליקציה נפתחת במסך מלא, בלי סרגל הדפדפן.
4. אחרי פתיחה אחת עם חיבור — היא עובדת אופליין לגמרי, כולל הפונט.

כשמתפרסמת גרסה חדשה מופיעה שורה "גרסה חדשה מוכנה" עם כפתור רענון.
ב-PWA שמותקן הדף כמעט אף פעם לא נסגר, ולכן בלי ההודעה אפשר להישאר
על גרסה ישנה בלי לדעת.

### הנתונים

נשמרים ב-IndexedDB של האתר, על המכשיר בלבד. **הסרת האפליקציה ממסך
הבית או ניקוי נתוני אתרים ב-Safari מוחקים אותם.** אין חשבון ואין ענן —
ייצוא גיבוי ממסך "נתונים" הוא באחריותך.

האפליקציה זוכרת מתי יוצא גיבוי מלא לאחרונה (הורדת הקובץ או העתקת ה-JSON
שהצליחה — לא העתקה ידנית, ולא הדוח לצ'אט). מסך "נתונים" מציג את התאריך,
ומסך "משקל" מזכיר כשיש נתונים ומעולם לא גובו, או כשעברו 14 ימים ומעלה
(`BACKUP_REMINDER_DAYS` ב-`src/lib/backup.ts`). התאריך נשמר ב-`settings`
ונכלל בגיבוי; בייבוא עם מיזוג נלקח המאוחר מבין השניים.

שתי נקודות שכדאי להכיר ב-iOS:

- הגרסה שמותקנת במסך הבית והגרסה שפתוחה ב-Safari **חולקות את אותו
  אחסון** כל עוד זו אותה כתובת. אין צורך להעביר נתונים ביניהן.
- אם תשנה את הכתובת שממנה האפליקציה מוגשת (למשל מעבר מ-GitHub Pages
  לדומיין משלך), זה origin אחר והנתונים לא יעברו. לייצא גיבוי לפני,
  ולייבא אחרי.

## מיגרציה מהגרסה הקודמת

הגרסה הקודמת (קובץ HTML יחיד) שמרה ב-`localStorage` תחת אותם מפתחות.
שתי דרכים להעביר את הנתונים:

- **אוטומטית** — אם פותחים את האפליקציה החדשה **מאותו origin** של
  הישנה, היא קוראת את `fatloss:weights` ו-`fatloss:workouts`
  מ-`localStorage` בטעינה הראשונה ומעתיקה אותם ל-IndexedDB. המקור
  לא נמחק, כך שאפשר לחזור לגרסה הישנה.
- **ידנית** — לייצא JSON מהגרסה הישנה, ובמסך "נתונים" לבחור קובץ או
  להדביק את הטקסט. הפורמט `{"v":1,"weights":[…],"workouts":[…]}`
  מתקבל כמו שהוא; שדות לא מוכרים (כמו `ts`) נזרקים בשקט. אחרי הייבוא
  מוצג כמה רשומות נכנסו וכמה נדחו ולמה.

ייבוא בברירת מחדל הוא **מיזוג** ולא מחיקה: רשומה מיובאת גוברת על אותו
תאריך או מזהה, ושום דבר קיים לא נמחק. "החלפה" היא בחירה מפורשת.

### פורמט האימונים — `schemaVersion: 2`

כל רשומת אימון שנשמרת היום נושאת `schemaVersion: 2`, וכל תרגיל בה
נושא את שמו כטקסט (`n`) לצד המזהה — כך שהיא מוצגת נכון גם אם התרגיל
ירד מהתוכנית או שינה שם.

בטעינה הראשונה אחרי העדכון, אם נמצאו ב-`fatloss:workouts` רשומות בלי
`schemaVersion`, מתבצעת המרה חד-פעמית:

1. המערך הגולמי כפי שהיה נכתב **פעם אחת** למפתח חדש `fatloss:workouts:v1`.
   אם המפתח כבר קיים הוא לא נדרס. אם הכתיבה נכשלת — ההמרה לא נכתבת
   לדיסק, והאפליקציה ממשיכה לעבוד מהזיכרון (ההעלאה-בקריאה עובדת כרגיל).
2. רק אחרי שהגיבוי קיים נכתב המערך המומר ל-`fatloss:workouts`, ומוצגת
   הודעה "N אימונים הומרו לפורמט החדש; עותק של המקור נשמר".

רשומה שלא ניתן להמיר (תאריך שבור, סוג אימון לא מוכר, לא אובייקט) **לא
נזרקת**: היא נשארת בסוף `fatloss:workouts` בדיוק כפי שהייתה, שורדת כל
שמירה, נכללת בגיבוי ה-JSON תחת `legacyWorkouts`, ומופיעה במסך אימונים
בסעיף "אימונים ישנים שלא הומרו" עם התאריך והסיבה. שום מפתח קיים לא
נמחק ולא נדרס בשום נתיב חוץ מ"מחק את כל הנתונים" המפורש, שמוחק גם את
`fatloss:workouts:v1`.

### לשנות את תוכנית האימונים

התוכנית כולה ב-`src/data/program-abc.json`. לכל אימון `code`, `title`
ורשימת תרגילים; לכל תרגיל:

- שדות ההנחיה שמוצגים כמו שהם: `name`, `sets`, `reps` (מחרוזת, למשל
  `"10-12"` או `"30-45 שנ'"`), `effort` (RIR — טקסט בלבד, לא שדה קלט;
  `"—"` הופך ל-`null`), `note` (מוצג מתחת לשם התרגיל כשאינו ריק),
  `videoUrl` (▶ קטן ליד השם, נפתח בטאב חדש עם `noopener noreferrer`;
  בלי כתובת — אין אלמנט בכלל), `muscle`.
- מה שהאפליקציה צריכה: `id`, `short` (לדוח), `machine`, `muscles`, `type`,
  `repRangeMin` / `repRangeMax` (מפורשים — אין פרסור של `reps` בזמן ריצה),
  `unilateral`, `isTimed`, `bodyweightOnly`, ו-`assisted` (גרוויטון: המשקל
  הוא סיוע).

`retired` באותו קובץ מחזיק תרגילים שירדו מהתוכנית, כזהות בלבד, כדי
שרישומים ישנים שלהם ימשיכו להיפתר ולהיות מוצגים במפרט הנכון.
`src/data/program.ts` רק טוען את ה-JSON וחושף את ה-API (`PROGRAM`,
`exerciseById`, `exerciseIn(t, id)` למפרט הספציפי לאימון — `leg-curl`
מופיע ב-A וב-B עם סטים שונים).

`type` (`compound` / `isolation` / `core`) הוא השדה המרכזי — הוא קובע את
משכי המנוחה בין סטים ובין תרגילים, דרך `REST_SECONDS` ב-`src/data/config.ts`.
אין לשכפל את הערכים האלה בתרגילים עצמם.

### מסך האימון

האפליקציה **מתעדת, לא מייעצת.** אין המלצות משקל, אין חיצים, אין הערות.
ההחלטה על משקל מתקבלת מחוץ לאפליקציה, פעם בשבוע; האפליקציה מציגה את
הנתונים שעליהם היא מתבססת.

- **מעל שדות הקלט של כל תרגיל** — שלושת הביצועים האחרונים של אותו
  תרגיל, לקריאה בלבד (`03/09 · 40 ק״ג · 12,12,10`), וטווח החזרות היעד
  מהתוכנית. בלי היסטוריה — "אין ביצוע קודם".
- **משקל אחד לתרגיל** (קפיצות 0.5 ק"ג), ומתחתיו שדה חזרות לכל סט.
  ברירת המחדל היא בדיוק המשקל מהביצוע האחרון. במודל הנתונים המשקל עדיין
  נשמר לכל סט (אותו ערך), כדי שרשומות ישנות עם משקל שונה בכל סט ימשיכו
  להיטען; ההיסטוריה מציגה אותן כמו שהן.
- **חימום — תרגיל 0.** בראש כל אימון: אופניים / הליכון, דקות (ברירת
  מחדל 10) ו"התחל" שמפעיל ספירה לאחור באותו טיימר של המנוחה, עם השהיה,
  איפוס ודילוג. הלחיצה על "התחל" היא מה שרושם את החימום ברשומה
  (`ex[0]`, `exerciseId: "warmup"`); עד אז השורה ריקה ואימון שנפתח בטעות
  נשאר טיוטה. אין מנוחה אחרי החימום.
- **אירובי סיום — התרגיל האחרון, כבוי.** אותו רכיב בתחתית האימון, נשלט
  על ידי `FINISHER_CARDIO_ENABLED` ב-`config.ts`. כלי של שלב 2 בתוכנית
  (מ-1/11/2026): בנוי כדי שלא יידרש שינוי קוד אז. כשמופעל — נשמר כתרגיל
  האחרון (`exerciseId: "finisher-cardio"`) ומוצג בהיסטוריה ובדוח.
- **טיימר מנוחה** נפתח אוטומטית בהזנת סט. משכים ב-`config.ts`:
  מורכב 90 שנ', בידוד 60, ליבה 60, ובין תרגילים 90.

**`id` הוא המפתח להיסטוריה, לא השם.** אפשר לשנות שם עברי בלי לנתק את
התרגיל מהרישומים שלו. תרגיל שמחליף שם לגמרי מקבל שורה ב-`EXERCISE_ALIASES`
שמצביעה מהשם הישן למזהה החדש. אין באפליקציה קטלוג תרגילים או בורר —
שינוי תוכנית הוא עריכת הקובץ.

## החלטות שכדאי להכיר

- **`toLocalISO` ולא `toISOString`.** כל מפתח תאריך הוא מקומי. המרה
  ל-UTC מזיזה שקילות ליום שכן. כל `ISODate` נבנה חזרה ל-`Date` בשעה
  12:00 מקומית, כדי שהוספת ימים לא תיפול בליל מעבר שעון.
- **שבוע = ראשון עד שבת.** "השבוע הנוכחי" נגזר תמיד מהשעון בזמן ריצה,
  מתעדכן בחצות ובכל חזרה לאפליקציה, ולעולם לא נשמר.
- **ממוצע נסכם באלפיות שלמות.** סכימה ישירה של ערכים כמו 80.1 צוברת
  שגיאת נקודה צפה, ו-80.025 היה מתעגל ל-80.02 במקום ל-80.03.
- **משקל לבדו אינו נתון.** שדה המשקל מאוכלס אוטומטית מהרישום האחרון,
  ולכן תרגיל נחשב "בוצע" רק אם נרשמה בו חזרה. אימון שנפתח בטעות נשאר
  טיוטה ולא מגיע לאחסון. חימום נחשב "בוצע" רק בלחיצה על "התחל".
- **כאב בדוח הוא הערך הגבוה של השבוע**, לא ממוצע.
- **תרגיל שדולג נכתב בדוח במפורש** — `· דולגו: פרפר, חתירת כבל` בסוף שורת
  האימון — כדי שהניתוח יבדיל בין "לא בוצע" ל"לא נרשם". "דולג" נגזר מהשורות
  הריקות שנשמרו עם הרשומה, כלומר ממה שהיה בתוכנית *באותו יום*, ולא מהתוכנית
  הנוכחית. אימון שלא נרשם בו דבר נשאר "לא נרשמו תרגילים" בלי פירוט.
  חימום ואירובי מופיעים בדוח רק אם בוצעו (`חימום אופניים 10 דק׳` ראשון,
  `אירובי הליכון 12 דק׳` אחרון), ולעולם לא ב"דולגו".
- **במסך אימונים יש שתי רשימות.** מתחת לניווט השבועות מופיעים האימונים של
  השבוע הנבחר, ו"היסטוריה" מציגה את 12 האחרונים בלי קשר לשבוע. הדרך לאימון
  ישן יותר היא לנווט לשבוע שלו — כמו רשת הימים במסך המשקל.
- **`ignoreVary` ב-service worker הוא חובה.** שרתים סטטיים רבים מחזירים
  `Vary: Origin`, ובלי זה כל התאמה ב-cache נכשלת והאפליקציה נראית ריקה
  אופליין.
- **אין המלצות.** היעד, סוג התנועה והדגלים עדיין מוקפאים ברשומה, כדי
  שרשומה ישנה תישאר מובנת גם אם התוכנית השתנתה — אבל שום דבר לא מחושב
  מהם. הרשומה מציגה מה היה; ההחלטה מתקבלת בחוץ.
- **אין הנחה על מספר הסטים בשום מקום.** בתוכנית יש תרגילים של 2 ושל 3,
  ו-`index + 1 === sets.length` הוא מה שקובע מתי נפתחת מנוחה בין
  תרגילים. `=== 3` היה משאיר את כל תרגילי ה-2 בלי מנוחה.
- **הטיימר שומר דדליין, לא מונה.** `setInterval` מצטבר נסחף כשהמסך כבוי;
  כאן כל טיק מחשב מחדש `deadline − Date.now()`. הוא חי ברמת האפליקציה
  ולא בתוך מסך האימון, כי מסכים מוחלפים בהחלפת טאב. השהיה (בחימום)
  שומרת את מה שנשאר במקום דדליין, ולכן טיימר מושהה לא פג לעולם.
- **מצב הממשק שורד רענון.** האימון הפתוח, התרגיל שבמוקד והדדליין נשמרים
  ב-`src/platform/uiState.ts`. זה **לא** נתוני משתמש: לא נכנס ל-IndexedDB
  ולא לגיבוי, ולכן `store.ts` נשאר שכבת האחסון היחידה של הנתונים.
- **צליל הטיימר מיוצר ב-WebAudio** ולא מקובץ — עובד אופליין בלי להוריד
  כלום. ויברציה תמיד, צליל ניתן לכיבוי.
- **כישלון כתיבה לא נבלע ולא נעלם.** הערך נשאר על המסך כדי שאפשר יהיה
  לייצא אותו, ולצדו אזהרה קבועה (שלא ניתנת לסגירה) שמפרטת אילו מפתחות
  לא הגיעו לדיסק, עם כפתור ניסיון חוזר. באנר שאפשר לסגור לא מספיק כאן —
  אחרי סגירה לא היה נשאר שום סימן שהנתון לא שמור.
- **"תחילת התוכנית" במסך נתונים** קובעת רק את מספר השבוע בכותרת הדוח.
  ברירת המחדל נגזרת מהנתון הראשון; אפשר לכוון אם ההיסטוריה באפליקציה
  מתחילה מאוחר יותר מהתוכנית עצמה.
