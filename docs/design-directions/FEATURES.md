# פיצ'רי נוחות — רשימה מתועדפת

שלב 1א · 30/10/2026 · ענף `design-directions`. מסמך תכנון בלבד, אפס שינויים בקוד.

**מקורות:** ממצאי האודיט (`docs/ui-audit/REPORT.md`, PR #27: F02–F26), וחמש אפליקציות שנלמדו כרפרנס עקרוני (MacroFactor, Hevy, Strong, Apple Fitness, Cronometer). לא הועתק מסך, לוגו או מראה.

**הגדרות:**
- **נוגע בנתונים** = מוסיף מפתח IndexedDB, שדה חדש ברשומה, או משנה פורמט גיבוי. כתיבת רשומות רגילות דרך הזרימות הקיימות (שקילה, רישום אוכל, סט) **אינה** נחשבת נגיעה. מצב ממשק ב-`localStorage` (`fatloss:ui:*`) אינו נתון ואינו בגיבוי.
- **מאמץ:** S ≤ חצי יום · M ≤ 2 ימים · L יותר.
- **עדיפות:** P1 = שימוש יומי, נכנס לשלבים הקרובים · P2 = ליטוש · P3 = אחר כך / לבדיקה.
- כל הפיצ'רים כאן **עובדים בשלושת הכיוונים**; ההבדל הוא מראה בלבד.

## פיצ'רים אסורים (סותרים את שיטת ההחלטה)

לא ייושמו באף שלב, גם אם אפליקציות הרפרנס עושות אותם:

- הבלטה של שינוי יומי במשקל — חצים, אדום/ירוק, "ירדת 0.3 מאתמול". השקילה היומית היא נקודה שקטה; רק הממוצע השבועי מדבר.
- streaks, ציונים, תגים, קונפטי, "כל הכבוד" — כל גיימיפיקציה.
- המלצות על מספרים בתזונה או בקלוריות מעבר למה שכבר קיים (יעד חלבון/קלוריות שהוזן ידנית ב-`fatloss:targets`).
- כל שינוי בלוגיקת R1–R6, בחישובי הממוצעים (7/7, חלקי), במותניים (רביעי/חמישי) או בסיכום השבועי. האב-טיפוס רק **מציג** את ההצעה הקיימת.
- דירוג/צביעה של יום לפי "הצלחה". יום סגור = נכנס לחישוב; יום פתוח = לא. זה כל הסטטוס.
